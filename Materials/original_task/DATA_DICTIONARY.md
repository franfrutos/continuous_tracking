# Data Dictionary (MIB Blocked Task)

Outputs generated by `mib_blocked/mib_blocked_task.py`.

## Root and participant folders

Root output directory:
- `MIB_DATA_DIR`
- default: `data/`

Per-participant folder structure:

```text
data/
└── participant_<participant_id>/
    ├── session_summary_p<participant_id>.csv
    ├── trial_summary_p<participant_id>.csv
    ├── continuous_responses_p<participant_id>.csv
    ├── button_events_p<participant_id>.csv
    └── tet_traces_p<participant_id>.csv
```

Accumulated file:
- `counterbalance_assignments.csv`
- location: root `data/` or `MIB_DATA_DIR`

`SESSION_ID` format: `YYYYMMDD_HHMMSS` and is retained as a column inside the CSV files, but no longer appears in the output filenames.

Important: rerunning the task with the same `participant_id` overwrites the previous files for that participant, because filenames are participant-based rather than session-based.

## 1) `session_summary_p<participant_id>.csv`

One row per session.

Useful columns:
- `session_id`
- `participant_id`, `participant_age`, `participant_gender`
- `data_dir`: root output directory
- `participant_data_dir`
- `session_data_dir`
- `assigned_order`
- `counterbalance_rule`
- `forced_block_order_raw`
- `block_size`
- `practice_trials_per_block`
- `trial_duration_s`
- `practice_trial_duration_s`
- `include_no_target_trials`: derived boolean (`1` if `no_target_trials_per_block > 0`, otherwise `0`)
- `peripheral_trials_per_block`
- `no_target_trials_per_block`
- `control_trials_per_block`
- `control_trial_mode`
- `control_target_ecc_cm`
- `tet_experimental_display_duration_s`
- `tet_experimental_trials`
- `calibration_duration_s`
- `sinusoidal_calibration_duration_s`
- `counterbalance_file`
- `button_events_file`
- `continuous_file`
- `tet_file`
- `trial_summary_file`

Note:
- `session_data_dir` now points to the same participant folder as `participant_data_dir`, kept for compatibility with earlier outputs.
- `block_size` now reflects the active experimental composition configured for that run.
- In `test` mode, each experimental block contains 2 trials by default. With the current default config, these are `1 peripheral` and `1` configured control trial. If `MIB_TEST_NO_TARGET_TRIALS_PER_BLOCK` is set above `0`, `no_target` trials are included accordingly.

## 2) `trial_summary_p<participant_id>.csv`

One row per trial, including:
- `phase = practice`
- `phase = calibration`
- `phase = experimental`

Core columns:
- `session_id`, `participant_id`
- `phase`, `block_index`, `block_type`
- `trial_global_index`, `trial_in_block`, `trial_type`
- `target_kind`
- `target_position_x_cm`, `target_position_y_cm`
- `target_contrast_mode`
- `response_mode`
- `duration_s`

Response summary columns:
- `button_press_count`
- `button_press_times_s`
- `n_response_samples`
- `mean_response_value`
- `min_response_value`
- `max_response_value`
- `final_response_value`
- `button_state_proportion`

Legacy-compatible columns retained:
- `mean_visibility`
- `min_visibility`
- `max_visibility`
- `final_visibility`

Interpretation:
- In `button`, `response_value` is binary in the time series, so `mean_response_value` is the proportion of samples with the button down.
- `button_state_proportion` duplicates that proportion explicitly for button trials.
- In `continuous`, `mean_response_value` is the mean of the continuous response over the trial.
- In `tet`, these sample-summary fields are usually empty because the response is stored in `tet_traces`.

Important `trial_type` values:
- `peripheral`
- `no_target`
- `static_mask`
- `near_fixation`
- `calibration_up`
- `calibration_down`
- `calibration_sinusoidal`

El valor por defecto de `control_trial_mode` es `near_fixation`.

## 3) `continuous_responses_p<participant_id>.csv`

Fixed-interval time series for `button` and `continuous`.

Columns:
- `session_id`
- `participant_id`
- `phase`
- `block_index`
- `block_type`
- `trial_global_index`
- `trial_in_block`
- `trial_type`
- `response_mode`
- `is_calibration`
- `time_s`
- `target_contrast`
- `target_contrast_true`
- `response_value`

Interpretation:
- `response_mode = button`: `response_value` is button state at each sample (`0` or `1`)
- `response_mode = continuous`: `response_value` is the potentiometer/slider value in `[0,1]`

Sampling:
- fixed temporal grid
- controlled by `MIB_RESPONSE_LOG_HZ`
- serial polling controlled by `MIB_DEVICE_QUERY_HZ`

## 4) `button_events_p<participant_id>.csv`

Discrete button events for button trials.

Columns:
- `session_id`
- `participant_id`
- `block_index`
- `block_type`
- `trial_global_index`
- `trial_in_block`
- `trial_type`
- `event_index`
- `event_time_s`

## 5) `tet_traces_p<participant_id>.csv`

Point-wise TET traces for practice and experimental TET trials.

Columns:
- `session_id`
- `participant_id`
- `tet_phase`
- `trial_index`
- `phase`
- `block_index`
- `block_type`
- `trial_global_index`
- `trial_in_block`
- `trial_type`
- `response_mode`
- `display_duration_s`
- `attempt_index`
- `point_index`
- `x_cm`
- `y_cm`
- `normalized_time`
- `normalized_visibility`

Properties:
- `normalized_time` in `0..1`
- `normalized_visibility` in `0..1`
- each row is one point of the trace
- each point can be linked unambiguously to its source trial through the block/trial metadata

Practice conventions:
- `phase = practice`
- `block_type = tet_practice`
- `response_mode = tet`
- `block_index = 0`

Experimental conventions:
- `phase = experimental`
- `block_type = tet`
- `response_mode = tet`

Sampling note:
- `tet_traces` is resampled onto the same fixed temporal grid used by `continuous_responses` (`MIB_RESPONSE_LOG_HZ`).
- This makes TET trials row-wise comparable to `button` and `continuous` trials of the same duration.

## 6) `counterbalance_assignments.csv`

Written in full mode only.

Columns:
- `session_id`
- `participant_id`
- `participant_age`
- `participant_gender`
- `assigned_at`
- `assigned_order`
